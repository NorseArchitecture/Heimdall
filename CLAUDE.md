## 1. What This Repository Is

Heimdall is **the gate** — `Norse.AuthN`: the authn story built on Himinbjörg, presenting login, register, forgot-password, 2FA setup, recovery, and reset uniformly across Blazor Server, WASM, and MAUI, plus the backing gRPC service. Code-wise this repo still depends on nothing above Asgard — `AuthN.Services` and `AuthN.Components` NorseRef only Asgard's `Abstractions.Contracts`/`Abstractions.Components` — but since Himinbjörg's `feature/identity-web-server` merge (`v0.0.5`) the dependency between the two realms is no longer one-directional: Himinbjörg's `Identity.Web.Server` NorseRefs this repo's `AuthN.Services` (to implement the gRPC contract) and `AuthN.Components.FluentUI` (to host the pages still migrating over), confirmed in Himinbjörg's own `csproj` and `CLAUDE.md`. Heimdall is not, therefore, unambiguously "topmost" in the submodule dependency chain anymore — it has a real consumer riding on it from a realm it also builds on.

`AuthN.Components`, `AuthN.Components.FluentUI`, and `AuthN.Services` are live — the Himinbjörg→Heimdall component migration moved the injection-clean subset (Login, Register, Logout, and their validators/requests) over mechanically; components with real backend injections (`UserManager`/`SignInManager`/`HttpContext`) still live on Himinbjörg's side, in `Identity.Web.Server`'s `Components/Pages/**` tree — that branch (`feature/identity-web-server`) merged to Himinbjörg's `master` and shipped as `v0.0.5`, and the gRPC wireup it was pending on is done (Himinbjörg's `AuthenticationService` implements this repo's `IAuthenticationService` for real, `LoginHandler`/`RegisterHandler` driving `SignInManager`/`UserManager` directly); what remains is only the page-by-page migration of that tree over here, still in progress, not a branch-merge blocker. `AuthN.Services` was hoisted out of `AuthN.Components` (2026-07-24) to isolate `IAuthenticationService` (the gRPC contract) and its wire records (`LoginRequest`, `RegisterRequest`, `LogoutRequest`, `LoginResult`, `LogoutResult`) from Razor/FluentValidation/Blazilla — a consumer who wants only the gRPC declarations, wrapped in their own components and wired to whatever backend they choose, references this thin assembly and nothing else. The hand-written `IAuthenticationGateway`/`AuthenticationResult` are retired (both interface and wrapper gone as of Asgard commit 5f06a88 which deleted `[GenerateGateway]`, `GatewayGenerator`, and all emission modes entirely). Components inject `IAuthenticationService` directly — the transport-dumb seam is DI substitution per host: Himinbjörg's `Identity.Web.Server` registers this repo's `AuthenticationService` implementation for Blazor Server; Yggdrasil (via Midgard) registers the generated gRPC client wiring for WASM. Components consume `Task<Outcome<T>>` from `IAuthenticationService` and pattern-match the result; there is no more `AuthenticationResult` wrapper anywhere. Himinbjörg's `Identity.Web.Server` and Yggdrasil's `Hosting.Web.Client`/`Hosting.Web.Server`/`Hosting.Stories.Client` already carry the correct split `using` statements (`Norse.AuthN.Components`/`.FluentUI` for the validators and markup, `Norse.AuthN.Services` for the contract and wire types) — confirmed against both repos' current source, this is no longer an open follow-up. Pages still carry the ASP.NET Identity scaffold's `/Account/*` routes deliberately — route renaming is a separate, deferred curation pass, not bundled into relocation.
